PROMPT 1 — ENTC REVISION DASHBOARD
Build one complete, self-contained HTML file with embedded CSS and JavaScript. Make a responsive ENTC student revision dashboard with a topic checklist and progress bar, adjustable countdown timer with start/pause/reset behavior, a multiple-choice quiz with feedback and score, revealable flashcards, and a daily goal field. Include at least five working interactive controls. Use sample study content, mobile-friendly layout, and no external libraries. Ensure every button works and the page runs by double-clicking the HTML file.

PROMPT 2 — SMART IRRIGATION EXPLORER
Build one complete, self-contained HTML file with embedded CSS and JavaScript for a beginner learning an ESP32-based smart irrigation concept. Include a soil-moisture slider, adjustable threshold, live pump ON/OFF simulation, conceptual block flow, expandable component notes, decision log with clear button, illustrative calibration input, safety checklist, and design-choice dropdowns. Use sample values only and clearly state it is a simulation, not a wiring diagram. Do not imply the page is connected to real hardware. Make it responsive and ensure all controls work.

PROMPT 3 — MICROCONTROLLER DECISION HELPER
Build one complete, self-contained HTML file with embedded CSS and JavaScript to compare ESP32, Arduino Uno family, and Raspberry Pi Pico family for beginner projects. Include sliders for budget, wireless, simplicity, and I/O priorities; project-type selector; live ranking; top recommendation explanation; comparison table; decision notes; reset control; and checklist. Mark scoring as illustrative and tell users to verify exact board variant specifications. Make every control work on laptop and phone.

TEST / IMPROVEMENT PROMPTS USED
1. Test every button, slider, dropdown, checkbox, timer, and quiz option. Fix any control that does not update the page.
2. Check the three HTML files at a narrow mobile width; ensure cards stack and text stays readable.
3. Ensure all pages work offline with no external scripts or assets.
4. Make safety and accuracy limitations clear wherever hardware or board selection is discussed.
5. Review the files and remove any claim that a simulation controls real hardware.
